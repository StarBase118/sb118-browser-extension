01The idea in one breath

SB118's stuff is scattered — HQ, the wiki, Discord, the main site, the Library, the sim archive, and (for staff) the forums, NocoDB, Authentik, n8n. This extension puts a single button in the browser toolbar that opens a popup with quick links to all of it, a search box that covers the wiki and sim archive, and personalized shortcuts to your ship and character. Staff see extra admin links and a cross-system member lookup that nobody else does.

The guiding constraint: it never touches passwords. It leans entirely on the Authentik single-sign-on session you already have — so it's safe to give to every member.

02Two pieces

The extension

A Manifest V3 extension — one shared codebase for Chrome/Edge/Brave, plus a small Firefox adaptation. It's a popup UI, a background worker (session checks, data fetch, badge polling), a content script (glossary tooltips), and local storage for your pinned links.

One HQ endpoint (the backbone)

A new /api/me route on HQ reads your Authentik session and hands back your ship, character, staff role, notification counts, and announcements. Everything personalized rides on this. Two small staff-only endpoints come later.

04How login works — no passwords

You're already signed in to Authentik SSO
→
Extension asks HQ /api/me using your session
→
200 = green light + your data · 401 = one-click login

The login light is just "did /api/me answer or not." Once you have an Authentik session, every SB118 link single-signs-on. The extension stores nothing sensitive and holds no API keys.

⚠ The one real risk — and how we de-risk it first

A request from an extension to HQ is technically cross-site, and Authentik's session cookie may be set to not travel on cross-site requests (SameSite). If so, a naive call would come back "signed out" even when you're not.

Plan: Phase 1 opens with a small spike that proves the extension can read your live session (running the request inside an HQ tab's context, where cookies always flow). If it can't be made to work cleanly, the personalized features fall back to a one-time manual "my ship / my character" setting and the extension still ships as a launcher + search tool. No catastrophic failure mode.

06The HQ endpoints

Four new routes on the megatool, all behind Authentik. Three read-only; one narrow write that only advances your own "last seen" marker so the badge can clear.

GET /api/me  Phase 1 — your profile, staff role, notification counts, announcements

POST /api/me/seen  Phase 3 — advance your own notification marker (the one exception to "no writes")

GET /api/staff/lookup  Phase 4 — cross-system member lookup, staff-only (403 otherwise)

GET /api/staff/feedback-count  Phase 4 — open feedback count, staff-only

07The build, in four phases

Whole product is specced; we build it across sessions, backbone first.

1
Launcher + backbone. Session-access spike → /api/me → extension skeleton, quick-launch, login light, my ship / my character, pinned links, staff tiering. Chromium + Firefox builds. This is the useful thing on its own.
2
Search. Unified search (wiki + forum archive; staff Discourse) with scope toggle. Plus the parked add-ons: address-bar and right-click search.
3
Awareness. Announcements feed and the notification badge (sims first, other sources as they become available).
4
Flavor + staff power-tools. Glossary tooltips, member lookup, feedback-queue peek.

08Guardrails

Security

No passwords, ever. Endpoints are Authentik-protected server-side — the popup's staff/member split is cosmetic, not a security boundary. No secrets in the bundle. Host permissions limited to SB118 domains by default.

Separation

New repo under the StarBase118 org. SB118 Authentik, SB118 infra, SB118 Cloudflare only. Nothing shared with CampaignHelp or MFC — SB118-only end to end.
